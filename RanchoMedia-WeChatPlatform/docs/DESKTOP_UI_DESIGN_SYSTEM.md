# RanchoMedia Desktop 2.0 · 第一阶段设计规范

先冻结统一组件与状态，再实现页面。现有 Web 编辑台和 Tkinter 入口保留，原稿、权限及 DPAPI 文件不得自动迁移或清空。

## 框架与密度

- 原生 Windows 标题栏，默认 1280×860 逻辑像素，最小 900×640；WebView2 负责 DPI 缩放。
- 左侧 208px 导航：工作台、内容库、发布中心、调度计划、评论互动、平台账号、运行日志。主区有面包屑、页标题与单一主操作；右侧 280px 回执/授权边界面板，窄窗口移至内容下方。
- 中文使用 Segoe UI / Microsoft YaHei UI；正文 13px，说明 12px，页面标题 24px，分组标题 14px。8px 间距栅格；控件高度 34px；组件圆角 6–10px；边框 1px。不使用渐变、玻璃或大面积装饰卡片。
- 默认跟随系统；浅色使用暖白背景、石墨色文字，深色使用中性炭灰。色彩只表示主操作、成功、警告、失败，信息不只靠颜色传递。

## 共享组件

`Button / Input / Badge / Panel / Alert / Skeleton / Dialog` 使用统一 Tailwind tokens、shadcn 组织方式及 Radix 行为；Lucide 图标 16px。全部控件有可见焦点、禁用、错误及加载状态。弹窗负责焦点管理；动画限 120ms，并尊重 reduced-motion。

## 公众号设置流程

1. 配置：名称、AppID、安全输入 AppSecret/可选现有 token。保存只写本地 DPAPI，不自动联网。已保存的秘密永不回填，留空保留原值。
2. 连接：显示最近一次真实回执与错误码；IP 白名单始终标为未验证/历史拒绝/已通过，只读核验需要明确按钮操作。
3. 草稿准备：显示既有稿件标题、封面文件及单稿 hash。独立确认后才允许官方 token/权限/封面/建稿/回查；公开发表与群发无入口。
4. 运行：五阶段进度、脱敏事件、成功 media_id 或确切阻塞。UNKNOWN 只允许核对，不自动重建；界面刷新不触发操作。

## 真实状态与测试

其余页面只读展示已有数据库/回执；尚未实现的编辑、分发和互动动作明确标记“第一阶段未接入”。没有桌面桥的浏览器预览显示未连接，不伪造业务数据。验收使用独立配置目录且禁网络执行；真实配置文件前后校验 SHA，不向远端发送测试内容。
